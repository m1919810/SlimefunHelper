# SlimefunHelper 模块开发速查

## 0. 统一注册管理（核心原则）

**所有事件监听、命令注册、热键绑定都必须通过 `BaseModule` 提供的注册方法完成**，以确保模块启用/禁用时能自动清理，避免内存泄漏和重复注册。

| 注册内容 | 推荐方法 | 说明 |
|---------|----------|------|
| 事件监听 | `registerListener(EventChannel, Consumer<Event<T>>)` | 自动绑定模块生命周期 |
| 命令树 | `registerCommandBootstrap(Consumer<MainCommand>)` | 在模块加载时构建命令 |
| 配置热键 | `hotkey()` / `toggleHotkey()` 构建器 | 自动注册到输入系统 |
| 任务调度 | `Tasks.scheduleXxx()` | 需手动管理取消，建议在 `onDisableModule` 清理 |

**禁止直接调用**：
- `Listener.registerPacketListener` 等静态方法（无法随模块自动卸载）
- `MainCommand.registerAsCommand` 不在 `registerCommandBootstrap` 中调用
- `SimpleInputManager.getInstance().registerHotKeys` 绕过 `BaseModule`

|------------|----------|

## 3. 事件监听（在 registerAll 中）

### 3.1 Event 类说明

所有事件回调都接收 `Event<T>` 对象，该类提供以下核心方法：

| 方法 | 说明 |
|------|------|
| `T context()` | 获取事件主体（如攻击事件中的 `HitResult`） |
| `Event<T> context(T val)` | 修改事件主体（需要 `canModifyContext` 为 true） |
| `boolean isCancelled()` | 检查事件是否已被取消 |
| `Event<T> cancel()` | 取消事件（需要 `canCancel` 为 true） |
| `<W> W getArgs(int idx)` | 获取额外参数（按声明顺序索引） |
| `boolean canCancel()` | 是否允许取消 |
| `boolean canModifyContext()` | 是否允许修改主体 |

**使用示例**：
|||java
private void onGameRender(Event<GameRenderer> event) {
// 获取额外参数
RenderTickCounter tickCounter = event.getArgs(0);
boolean isRenderWorld = event.getArgs(1);

    // 取消事件（如果允许）
    if (someCondition && event.canCancel()) {
        event.cancel();
    }
}

private void onChatSend(Event<String> event) {
// 修改消息内容（如果允许）
if (event.canModifyContext()) {
event.context("[Prefix] " + event.context());
}
}
|||

### 3.2 事件通道获取规范

**所有事件通道（包括 `Listener` 和 `RenderListener` 中的通道）都必须通过对应的 `getter` 方法访问**，禁止直接访问静态字段。

| 类 | 正确方式 | 错误方式 |
|---|----------|----------|
| `Listener` | `Listener.getPostGameTick()` | `Listener.postGameTick` |
| `Listener` | `Listener.getPacketPoint()` | `Listener.packetPoint` |
| `RenderListener` | `RenderListener.getRenderLayerTasks()` | `RenderListener.renderLayerTasks` |

**注册示例**：
|||java
// 基础事件
registerListener(Listener.getPostGameTick(), this::onTick);
registerListener(Listener.getAttackAction(), this::onAttack);
registerListener(RenderListener.getRenderLayerTasks(), this::onRender);

// 精确网络包事件（避免使用 getPacketSendPoint/getPacketAcceptPoint）
registerListener(Listener.getPacketPoint().getChannel(PlayerInteractBlockC2SPacket.class), this::onInteractBlock);
registerListener(Listener.getPacketPreHandlePoint().getChannel(BlockUpdateS2CPacket.class), this::onBlockUpdate);
registerListener(Listener.getPacketPostHandlePoint().getChannel(DisconnectS2CPacket.class), this::onDisconnect);
|||

### 3.3 常用基础通道

- `Listener.getPostGameTick()` – 每 tick 结束后，玩家存在时
- `Listener.getPreTick()` – 每 tick 开始前
- `Listener.getAttackAction()` – 玩家攻击（可取消）
- `Listener.getPlayerTravelingTick()` – 玩家移动处理前（可取消）
- `Listener.getCustomListener()` – 自定义事件分发器

### 3.4 网络包精确通道（推荐）

**避免使用** `Listener.getPacketSendPoint()` 或 `Listener.getPacketAcceptPoint()`（会收到所有包，性能差且易出错）。  
**推荐使用** `getPacketPoint()`、`getPacketPreHandlePoint()`、`getPacketPostHandlePoint()`、`getPacketPostSendPoint()` 的 `getChannel(Class)` 方法。

| 通道 | 时机 | 特性 |
|------|------|------|
| `getPacketPoint().getChannel(Class)` | 包读写时 | 可取消、可修改 |
| `getPacketPreHandlePoint().getChannel(Class)` | 主线程处理前 | 可取消 |
| `getPacketPostHandlePoint().getChannel(Class)` | 主线程处理后 | 广播，不可取消 |
| `getPacketPostSendPoint().getChannel(Class)` | 包已发送后 | 广播 |

## 7. 辅助方法

- `checkNull()`：mc.player/world 非空
- `mc.execute(Runnable)`：主线程执行
- `Debug.chat(String)`：发送聊天消息
- `RenderUtils.drawXxx`：渲染辅助（需在渲染事件中）

## 8. 生命周期

| 方法 | 时机 |
|------|------|
| 构造器 | 实例化 |
| `registerAll()` | `onCreate()` 自动调用（应在其中注册事件/命令） |
| `onEnableModule()` | Flag 变 true |
| `onDisableModule()` | Flag 变 false（清理运行时状态、取消自定义任务） |
| `onRemove()` | 模块移除（自动清理所有通过 BaseModule 注册的监听器和命令） |

## 9. 完整示例

|||java
public class AutoJump extends BaseModule {
public static final String[] ENABLE = makePath("auto-jump.enable");
public AutoJump() { bindFlag(enable); }
public final FlagRef enable = flagBuilder(Configs.MOV_CONFIG, ENABLE).build();
private int counter;
@Override public void onEnableModule() { counter = 0; }
@Override public void registerAll() {
super.registerAll();
registerListener(Listener.getPostGameTick(), this::onTick);
}
private void onTick(Event<ClientPlayerEntity> event) {
if (!enable.get()) return;
if (mc.player.isOnGround()) {
if (++counter >= 5) {
mc.player.jump();
counter = 0;
}
} else counter = 0;
}
}
|||

## 10. 常见错误 ❌

- ❌ 直接访问 `Listener.postGameTick` → 应使用 `Listener.getPostGameTick()`
- ❌ 直接访问 `RenderListener.renderLayerTasks` → 应使用 `RenderListener.getRenderLayerTasks()`
- ❌ 直接调用 `Listener.registerSinglePacketListener` → 应使用 `registerListener(Listener.getPacketPoint().getChannel(XXX.class), ...)`
- ❌ 使用 `getPacketSendPoint()` 或 `getPacketAcceptPoint()` 监听所有包 → 应使用 `getPacketPoint().getChannel(Class)` 精确监听
- ❌ 在 `registerAll` 外调用 `registerCommandBootstrap` → 必须放在 `registerAll` 内
- ❌ 手动创建 `SimpleHotKey` 并注册到 `SimpleInputManager` → 应使用 `hotkey()` 构建器
- ❌ 在 `onEnableModule` 中重复注册事件 → 事件只需在 `registerAll` 注册一次，模块禁用时会自动取消
- ❌ 错误获取事件额外参数 → 使用 `event.getArgs(index)` 而非直接访问字段
- ❌ 在 lambda 中编写复杂业务逻辑 → 应提取为私有方法，使用 `this::method` 或简洁 lambda 调用
- ❌ 未检查 `canCancel`/`canModifyContext` 就直接调用 `cancel()` 或 `context(val)` → 必须先用对应 getter 检查
