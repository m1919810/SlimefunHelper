# SlimefunHelper 模块开发速查

## 0. 统一注册管理（核心原则）

**所有事件监听、命令注册、热键绑定都必须通过 `BaseModule` 提供的注册方法完成**，以确保模块启用/禁用时能自动清理，避免内存泄漏和重复注册。

| 注册内容 | 推荐方法 | 说明 |
|---------|----------|------|
| 事件监听 | `registerListener(EventChannel, Consumer<Event<T>>)` | 自动绑定模块生命周期 |
| 命令树 | `registerCommandBootstrap(Consumer<MainCommand>)` | 在模块加载时构建命令 |
| 配置热键 | `hotkey()` / `toggleHotkey()` 构建器 | 自动注册到输入系统 |
| 任务调度 | `Tasks.scheduleXxx()` | 需手动管理取消，建议在 `onDisableModule` 清理 |

**禁止直接调用**：
- `Listener.registerPacketListener` 等静态方法（无法随模块自动卸载）
- `MainCommand.registerAsCommand` 不在 `registerCommandBootstrap` 中调用
- `SimpleInputManager.getInstance().registerHotKeys` 绕过 `BaseModule`

## 2. 配置类型

| 类型       | 构建示例                                                                                                                    |
|------------|-------------------------------------------------------------------------------------------------------------------------|
| FlagRef    | `FlagRef ref = flagBuilder(Config, path).build();// 注意flagBuilder不能接defaultValue`                                       |
| IntRef     | `IntRef ref = builder(Config, path, IntRef.TYPE).defaultValue(1).build()`                                               |
| DoubleRef  | `DoubleRef ref = builder(Config, path, DoubleRef.TYPE).defaultValue(1.0).build()`                                       |
| EnumRef    | `EnumRef<E> ref = builder(Config, path, Class<E extends Enum & ConfigEnum> ).defaultValue(E.VAL).build()`               |
| KeyBindRef | `KeyBindRef ref = hotkey(Config, path).defaultValue(new MultiKeyBind(...)).registerHotkey(...).build()`                 |
| NBTRef | `NBTRef<E extends NBTParsable> nbtRef = builder(Config, path, NBTType.<E>parameter(E.class)).defaultValue(...).build()` |

链式方法：`.defaultValue()` `.validator()` `.updateListener()` `.hideConfig()`

NBTRef说明: 为复杂的数据结构,每个NBTParsable与NBTType绑定,NBTType实现了其Codec， StringifyFactory和WidgetFactory 用于生成复杂的配置文件界面配置项

常用NBTParsable: 
```java
new Regex("regexString"); new RegistryRegex(new Regex("..."), Registries.ITEM); new WrapColor(TextColor.fromRgb(...));new EntryPrimitiveMap<T, W>(Registry<T>, NBTType<W>, Map<T, W> map); new PrimitiveList<W>(NBTType<W> type, List<W> list);
```

常用NBTTypes: 有些基础类型并非NBTParsable,但是我们可以引用他们的NBTType, 我们称它PrimitiveTypes 他们也会被录入PRIMITIVE_TYPE注册表 如下:
```java
// interface me.matl114.hacks.utils.config.NBTTypes
public NBTType<Integer> INT_TYPE;

public NBTType<Double> DOUBLE_TYPE;

public NBTType<Boolean> BOOLEAN_TYPE;

public NBTType<String> STRING_TYPE;

public NBTType<TextColor> COLOR_TYPE ;

public NBTType<Registry<?>> REGISTRY_TYPE ;

public NBTType<Pattern> REGEX_TYPE;

public NBTType<Identifier> IDENTIFIER_TYPE;

public NBTType<NbtElement> NBT_ELEMENT_TYPE;
public NBTType<NbtCompound> NBT_COMPOUND_TYPE;
// initialize with fields above
public static Map<String, NBTType<?>> PRIMITIVE_TYPES = ...;

public static <T> NBTType<T> primitiveTypes(String string) {
    return (NBTType<T>) PRIMITIVE_TYPES.get(string);
}

public static Codec<NBTType<?>> CODEC = Codec.STRING.flatXmap(
    s -> {
        var nbtType = primitiveTypes(s);
        return nbtType == null ? DataResult.error(() -> "Not found") : DataResult.success(nbtType);
    },
    t -> {
        if (PRIMITIVE_TYPES.containsKey(t.typeName())) {
            return DataResult.success(t.typeName());
        } else {
            return DataResult.error(() -> "Not a primitive type: " + t.typeName());
        }
    });

```

## 3. 事件监听（在 registerAll 中）

### 3.1 Event 类说明

所有事件回调都接收 `Event<T>` 对象，该类提供以下核心方法：

| 方法 | 说明 |
|------|------|
| `T context()` | 获取事件主体（如攻击事件中的 `HitResult`） |
| `Event<T> context(T val)` | 修改事件主体（需要 `canModifyContext` 为 true） |
| `boolean isCancelled()` | 检查事件是否已被取消 |
| `Event<T> cancel()` | 取消事件（需要 `canCancel` 为 true） |
| `<W> W getArgs(int idx)` | 获取额外参数（按声明顺序索引） |
| `boolean canCancel()` | 是否允许取消 |
| `boolean canModifyContext()` | 是否允许修改主体 |

**使用示例**：
|||java
private void onGameRender(Event<GameRenderer> event) {
// 获取额外参数
RenderTickCounter tickCounter = event.getArgs(0);
boolean isRenderWorld = event.getArgs(1);

    // 取消事件（如果允许）
    if (someCondition && event.canCancel()) {
        event.cancel();
    }
}

private void onChatSend(Event<String> event) {
// 修改消息内容（如果允许）
if (event.canModifyContext()) {
event.context("[Prefix] " + event.context());
}
}
|||

### 3.2 事件通道获取规范

**所有事件通道（包括 `Listener` 和 `RenderListener` 中的通道）都必须通过对应的 `getter` 方法访问**，禁止直接访问静态字段。

| 类 | 正确方式 | 错误方式 |
|---|----------|----------|
| `Listener` | `Listener.getPostGameTick()` | `Listener.postGameTick` |
| `Listener` | `Listener.getPacketPoint()` | `Listener.packetPoint` |
| `RenderListener` | `RenderListener.getRenderLayerTasks()` | `RenderListener.renderLayerTasks` |

**注册示例**：
|||java
// 基础事件
registerListener(Listener.getPostGameTick(), this::onTick);
registerListener(Listener.getAttackAction(), this::onAttack);
registerListener(RenderListener.getRenderLayerTasks(), this::onRender);

// 精确网络包事件（避免使用 getPacketSendPoint/getPacketAcceptPoint）
registerListener(Listener.getPacketPoint().getChannel(PlayerInteractBlockC2SPacket.class), this::onInteractBlock);
registerListener(Listener.getPacketPreHandlePoint().getChannel(BlockUpdateS2CPacket.class), this::onBlockUpdate);
registerListener(Listener.getPacketPostHandlePoint().getChannel(DisconnectS2CPacket.class), this::onDisconnect);
|||

### 3.3 常用基础通道

- `Listener.getPostGameTick()` – 每 tick 结束后，玩家存在时
- `Listener.getPreTick()` – 每 tick 开始前
- `Listener.getAttackAction()` – 玩家攻击（可取消）
- `Listener.getPlayerTravelingTick()` – 玩家移动处理前（可取消）
- `Listener.getCustomListener()` – 自定义事件分发器

### 3.4 网络包精确通道（推荐）

**避免使用** `Listener.getPacketSendPoint()` 或 `Listener.getPacketAcceptPoint()`（会收到所有包，性能差且易出错）。  
**推荐使用** `getPacketPoint()`、`getPacketPreHandlePoint()`、`getPacketPostHandlePoint()`、`getPacketPostSendPoint()` 的 `getChannel(Class)` 方法。

| 通道 | 时机 | 特性 |
|------|------|------|
| `getPacketPoint().getChannel(Class)` | 包读写时 | 可取消、可修改 |
| `getPacketPreHandlePoint().getChannel(Class)` | 主线程处理前 | 可取消 |
| `getPacketPostHandlePoint().getChannel(Class)` | 主线程处理后 | 广播，不可取消 |
| `getPacketPostSendPoint().getChannel(Class)` | 包已发送后 | 广播 |

## 9. 完整示例

|||java
public class AutoJump extends BaseModule {
public static final String[] ENABLE = makePath("auto-jump.enable");
public AutoJump() { bindFlag(enable); }
public final FlagRef enable = flagBuilder(Configs.MOV_CONFIG, ENABLE).build();
private int counter;
@Override public void onEnableModule() { counter = 0; }
@Override public void registerAll() {
super.registerAll();
registerListener(Listener.getPostGameTick(), this::onTick);
}
private void onTick(Event<ClientPlayerEntity> event) {
if (!enable.get()) return;
if (mc.player.isOnGround()) {
if (++counter >= 5) {
mc.player.jump();
counter = 0;
}
} else counter = 0;
}
}
|||

## 10. 常见错误 ❌

- ❌ 直接访问 `Listener.postGameTick` → 应使用 `Listener.getPostGameTick()`
- ❌ 直接访问 `RenderListener.renderLayerTasks` → 应使用 `RenderListener.getRenderLayerTasks()`
- ❌ 直接调用 `Listener.registerSinglePacketListener` → 应使用 `registerListener(Listener.getPacketPoint().getChannel(XXX.class), ...)`
- ❌ 使用 `getPacketSendPoint()` 或 `getPacketAcceptPoint()` 监听所有包 → 应使用 `getPacketPoint().getChannel(Class)` 精确监听
- ❌ 在 `registerAll` 外调用 `registerCommandBootstrap` → 必须放在 `registerAll` 内
- ❌ 手动创建 `SimpleHotKey` 并注册到 `SimpleInputManager` → 应使用 `hotkey()` 构建器
- ❌ 在 `onEnableModule` 中重复注册事件 → 事件只需在 `registerAll` 注册一次，模块禁用时会自动取消
- ❌ 错误获取事件额外参数 → 使用 `event.getArgs(index)` 而非直接访问字段
- ❌ 在 lambda 中编写复杂业务逻辑 → 应提取为私有方法，使用 `this::method` 或简洁 lambda 调用
- ❌ 未检查 `canCancel`/`canModifyContext` 就直接调用 `cancel()` 或 `context(val)` → 必须先用对应 getter 检查

## 11. MovementModifier 注册（LegalMovementManager 管道）

当模块需要介入玩家的合法移动逻辑（例如鞘翅飞行增强、速度调整等）时，必须实现 `LegalMovementManager.MovementModifier` 接口，并通过 **`DelegateMovementModifier`** 注册到玩家的移动管道中。

### 11.1 接口方法说明

| 方法 | 调用时机 | 用途 |
|------|----------|------|
| `applyPreTickModify(Event<LegalMovementManager>)` | 玩家 tick **开始前**（最早阶段） | 初始化或重置每 tick 状态 |
| `applyAfterInputTick(Event<LegalMovementManager>)` | 玩家输入处理**之后** | 基于原始玩家输入做修改（如移动速度调整） |
| `applyBeforeTravelTick(Event<LegalMovementManager>, Event<Vec3d>)` | `travel` 方法调用**之前** | 修改即将传递给物理引擎的移动向量 |
| `applyAfterTravelTick(Event<LegalMovementManager>, Event<Vec3d>)` | `travel` 方法调用**之后** | 对物理计算后的结果进行后处理（较少用） |
| `applyBeforeInputPacketModify(Event<LegalMovementManager>)` | 玩家输入包发送**之前** | 修改即将发送给服务端的输入包内容 |
| `applyBeforeMovementPacketModify(Event<LegalMovementManager>)` | 移动包发送**之前** | 修改位置/动作包（高级用途） |
| `postModify(Event<LegalMovementManager>, boolean)` | 玩家 tick **结束后** | 清理状态，返回 `true` 表示本次修改仍有效，返回 `false` 则该 modifier 将被自动移除 |

### 11.2 管道类型

| 管道常量 | 注入位置 | 用途 |
|----------|----------|------|
| `MovTasks.PLAYER_PIPELINE_POS` | 位置修改管道 | **修改玩家移动向量**，影响最终位置。适用于 `applyBeforeTravelTick` 等。 |
| `MovTasks.PLAYER_PIPELINE_0` | 普通监听管道 | 仅监听玩家 tick 各阶段，**不修改移动向量**。适用于纯观测或辅助逻辑。 |

### 11.3 注册示例（在模块构造器中）

```java
public static LegalMovementManager.DelegateMovementModifier instance;

public ElytraFlightLegit() {
    bindFlag(enable);
    if (instance == null) {
        instance = new LegalMovementManager.DelegateMovementModifier(this::cast);
        // 注册到位置修改管道，使 applyBeforeTravelTick 等方法生效
        MovTasks.PLAYER_PIPELINE_POS.addMovementModifierFactory(() -> instance);
    }
    instance.setDelegate(this::cast);
}
```


注意：

DelegateMovementModifier 构造参数为一个返回 MovementModifier 实例的 Supplier。

通过 setDelegate(Supplier) 可动态切换实际生效的 modifier（例如模块禁用时返回一个空实现）。

必须在管道中注册，否则接口方法不会被调用。

无需手动移除管道中的modifier，因为在下一个相同模块创建的时候会自动顶替上一个模块
